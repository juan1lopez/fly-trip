# Iteración 2: Skiplagged, Google 0.10.0, búsqueda por mes y nueva interfaz. Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** add Skiplagged as a third source, bring Google Flights back with `fli` 0.10.0, add month search with a per-day price calendar, and restyle the web as dark option A, all without losing any behavior from milestone 1.

**Architecture:** the same layers (core → sources → engine → web → cli). The work splits into:
- Skiplagged: a new source in `sources/skiplagged.py`, with an MCP JSON-RPC client in the same style as Kiwi.
- Month logic: in `core/months.py` and `core/calendar.py`, both pure.
- The engine: adds Skiplagged as a second "confirming" source, and a calendar phase in month mode.
- The web: rewrites its templates and CSS following `docs/design/mockup-a.html`.

**Tech Stack:** the same as milestone 1, with `flights` pinned to git `https://github.com/punitarani/fli` at commit `881aee5` (version 0.10.0).

**Spec:** `docs/superpowers/specs/2026-11-09-iteracion-2-fuentes-mes-interfaz-design.md` (iteration 2). Milestone 1's spec still applies.

## Global Constraints

**Everything from milestone 1 still applies.**
- Language: Latin American Spanish for the UI and docs, English for code.
- USD.
- `America/Argentina/Mendoza`.
- Tests stay offline.
- Polite use of sources, with no evasion.
- Web on 127.0.0.1 only.
- `fly check` stays green.

**Skiplagged**
- URL `https://mcp.skiplagged.com/mcp`, sent with `User-Agent: fly-trip/0.1 (uso personal)`.
- `includeHiddenCity=false` ALWAYS. Also filter out any item that is still marked as hidden city.
- At most 12 `sk_flights_search` calls per search and 3 at a time.
- At most 12 calendar calls per search and 3 at a time.
- Pause it for 60 min on a 429, and stop the calls queued behind it.
- When every call returns empty, treat it as "posible bloqueo" (error plus pause), the same as Google.

**Months**
- 1 to 4 consecutive months, in `AAAA-MM` format.
- The default is the current month and the next two.
- The window runs from the first day of the first month to the last day of the last month. If today falls inside the window, it starts tomorrow.

**Calendar**
- The price is labeled "precio orientativo (Skiplagged)".
- The value per day is the minimum over the origins of (price + that origin's transfer).
- The cheapest 10% of days are highlighted.

**Visual system**
- Colors: `#0d0d0d`, `#1c1c1c`, `#262626`, lime `#d4ff3a`, text `#f5f5f2`, secondary `#9a9a96`, amber `#ffb547`, coral `#ff6b5e`.
- Fonts: Manjari and Inter from Google Fonts, with system fallbacks.
- Corners 20–24 px, and pills for buttons and tags.
- One column below 900 px.

**Contracts that must not change**
- The `.itinerary` and `.origin-card` classes.
- The `status_label` texts.
- `/buscar/validar`.
- `refrescar=1`.
- `failed_origins`.
- TrustedHost and Origin.
- `FLYTRIP_TODAY`.

## Review Focus

1. Skiplagged must never show hidden city, even if the API ignores the parameter. Covered by Task 2.
2. A month window that includes today starts tomorrow, never on a past day. Covered by Task 3.
3. A calendar with days missing or no data at all renders without errors and says "no disponible". Covered by Task 5.
4. When Skiplagged fails, the rest of the search still shows results, and its status is visible. Covered by Task 4.
5. The `fli` 0.10.0 upgrade keeps "one fetch = one HTTP request", or documents the change. Covered by Task 1.

### Task 2: Skiplagged source

**Files:**

  - `src/flytrip/devtools/record.py`: add the `record skiplagged` command (search and calendar).

**Interfaces (Produces):**
- Constants:
  - `SKIPLAGGED_URL = "https://mcp.skiplagged.com/mcp"`;
  - `SKIPLAGGED_HEADERS`, which includes the User-Agent;
  - `SKIPLAGGED_MAX_CONCURRENCY = 3`.
- `build_search_arguments(request: SourceRequest) -> dict[str, object]`:
  - It requires exact dates, the same as Google; otherwise it raises `ValueError("Skiplagged solo confirma fechas exactas")`.
  - It sends `origin`, `destination`, `departureDate` (ISO), `returnDate` (when there are nights), `currency="USD"`, `adults`, `sort="price"`, `limit=20`, `includeHiddenCity=False` and `includeVirtualInterlining=request.allow_separate_tickets`.
- `build_calendar_arguments(origin: str, destination: str, anchor: date, return_date: date | None) -> dict[str, object]`.
- `normalize_search(rpc: dict[str, Any], *, origin: str, adults: int, fetched_at: datetime) -> list[Itinerary]`:
  - It reads from `structuredContent.flights`.
  - It DISCARDS any item that is hidden city.
  - It maps virtual interlining to `separate_tickets=True`, standard to `False`, and anything unknown to `None`.
  - The booking URL is the item's link (the `searchUrl` plus the trip hash). Only `https://` URLs are accepted.
  - It applies `normalize_flight_number`, and drops the offset from times to get naive local times.
- `normalize_calendar(rpc: dict[str, Any]) -> list[tuple[date, Decimal]]`.
- `CalendarResult(source: str, status: Literal["ok", "paused", "error", "timeout"], days: tuple[tuple[date, Decimal], ...] = (), detail: str = "", latency_ms: int = 0)`, a frozen dataclass.
- `class SkiplaggedSource`:
  - `name = "skiplagged"`.
  - `__init__(self, client: httpx.AsyncClient, url: str = SKIPLAGGED_URL, clock = utc_now)`.
  - `async search(self, request: SourceRequest) -> SourceResult`. It handles a 429 by raising `SourceBlocked` and setting `_blocked_until`. Calls queued behind a 429 do not go out. HTTP and tool errors become an "error" with a Spanish detail.
  - `async calendar(self, origin: str, destination: str, anchor: date, return_date: date | None) -> CalendarResult`. It never raises.
  - `async aclose(self) -> None`.

### Task 3: Month mode in core and CLI

**Files:**
- Create: `src/flytrip/core/months.py` and `tests/core/test_months.py`.
- Modify: `src/flytrip/core/query.py` (add `calendar: bool = False` to `SearchQuery`, and include it in `cache_key`), `src/flytrip/cli.py` (flags) and `tests/cli/test_search_cli.py`.

**Interfaces:**
- `parse_month(value: str) -> tuple[int, int]`. It raises `ValueError` for an invalid format.
- `default_months(today: date) -> list[str]`. It returns the current month and the next two, for example `["2026-11", "2026-12", "2027-01"]`.
- `validate_months(first: str, last: str | None, today: date) -> list[str]`. It returns these messages:
  - "Mes inválido: {v}. Usa AAAA-MM."
  - "El mes 'hasta' no puede ser anterior al mes 'desde'."
  - "Puedes elegir hasta 4 meses."
  - "Ese mes ya pasó: {v}."
- `months_window(first: str, last: str | None, today: date) -> tuple[date, date]`. It returns `(max(first day, today + 1), last day of the last month)`.
- CLI: `fly search DESTINO --mes AAAA-MM [--hasta-mes AAAA-MM] (--noches A-B | --solo-ida)`.
  - Either `--mes` OR `--desde`/`--hasta`, never both. Using both exits with code 2 and the message "Usa --mes o --desde/--hasta, no los dos.".
  - With `--mes`, the query is built with `calendar=True`.

### Task 4: Engine with Skiplagged and calendar (after Tasks 1 to 3)

**Files:**
- Create: `src/flytrip/core/calendar.py` and `tests/core/test_calendar.py`.
- Modify:
  - `src/flytrip/engine/search.py`, `engine/factory.py` and `devtools/demo.py` (replay for Skiplagged and the calendar);
  - `src/flytrip/web/views.py`: `SOURCE_NAMES["skiplagged"] = "Skiplagged"`;
  - `src/flytrip/cli.py`: a line with the best day per month;
  - the matching tests.

**Interfaces:**
- `CalendarDay(day: date, price_usd: Decimal, origin: str)`, a frozen pydantic model.
- `build_calendar(entries: Iterable[tuple[str, date, Decimal]], transfers: Mapping[str, TransferCost | None]) -> list[CalendarDay]`. It takes the minimum per day of price + `transfer.cost_usd_roundtrip`, and sorts by day.
- `cheap_days(days: Sequence[CalendarDay], fraction: Decimal = Decimal("0.1")) -> set[date]`. It returns at least 1 day if there is data.
- `month_grid(year: int, month: int) -> list[list[date | None]]`. Weeks start on Monday.
- `SearchSnapshot` gains `calendar: tuple[CalendarDay, ...] = ()` and `calendar_note: str = ""`. Both have defaults, so the old cache stays valid.
- `SearchEngine(..., skiplagged: SkiplaggedSource | None = None, ...)`:
  - **Confirmation phase:** Google and Skiplagged both receive the candidate pairs, each with its own budget (12 fetches for Google; 12 calls for Skiplagged), and run concurrently.
  - **Calendar phase** (only when `query.calendar`):
    - It runs concurrently with Kiwi.
    - It makes one call per origin and per month in the window, with the anchor on the 15th, or on the window's start day if that is later.
    - `return_date = anchor + nights_min` for round trips.
    - It filters the days that fall inside the window.
  - `statuses` includes "skiplagged".
  - Statuses: partial, all-empty → block, and paused, the same as for Google.
  - When every calendar call fails, `calendar_note = "Calendario no disponible: {motivo}"`.
  - `aclose` closes Skiplagged too.
- `build_engine` wires `SkiplaggedSource(httpx.AsyncClient(timeout=20))`.
- `build_demo_engine` replays Skiplagged and the calendar from the fixtures, with a delay of about 1 s.
